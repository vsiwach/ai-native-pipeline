01

What the MVP proves — and what it deliberately doesn’t

The strategy’s own honesty section calls trajectory-level parity “the least-proven claim in the plan.” This MVP attacks exactly that gap with the machinery of PRD Figure 1: shadow → certify → promote → instant rollback, run end-to-end on a real agent route. It does not claim the 40% decode advantage — that is Phase 0’s independent-benchmark work. It claims something a viewer can verify in the room: a route moved off a frontier API onto open silicon at certified quality — vendor-blind by construction — with every number measured and every artifact rerunnable.

CERTIFIED MIGRATION · F1.2 + F1.3

Live traffic shadowed onto a candidate at zero user risk; quality certified against a hash-attested eval set; a signed (ed25519) certificate binds eval hash + model build + route config; promotion is one gesture, rollback is instant and armed for the life of the route.

PROOF HARNESS · F0.2 SLICE

One command — ./dev bench — measures p99 TTFT/TPOT and derives $/Mtok only from measured tokens/sec × declared pool price, for each pool. Reports embed the request profile so anyone can rerun them. SLO gates at p99, never averages.

VENDOR-BLIND · BY CONSTRUCTION

The incumbent slot takes any OpenAI-compatible endpoint; the candidate slot takes any pool the MAX runtime serves. Today that candidate is NVIDIA A100 serverless capacity; AMD is the same buttons the day healthy MI300X capacity exists — zero code changes, and the gap is stated below, not papered over.

02

The route: a voice workload, grounded in Modular’s own docs

The migrated route is voice-agent — a voice workload: short conversational turns answered by a retrieval-grounded agent over Modular’s public documentation (MAX, Mojo, Mammoth, the skills repo). Voice is the least forgiving serving workload — the SLO of record is TTFT p99 < 500 ms, TPOT p99 < 60 ms — which is exactly why it anchors the demo: the measured MAX numbers (p99 TTFT 308.5 ms, TPOT 20.8 ms) pass it outright. Every answer must cite the retrieved sources; ungrounded answers fail certification by construction. It is packaged as a skill in the conventions of Modular’s own skills repo — intended as a contribution, not a fork — and served MAX-first on both pools, with the bring-up driven by Modular’s import-model and debug-model skills: the §4.2 flywheel, demonstrated rather than described. A viewer can ask it anything, live, and watch which silicon answers.

WHAT IS MEASURED, WHAT IS NOT — STATED PLAINLY

Measured: every latency, every tokens/sec, every open-pool $/Mtok (pod price ÷ measured throughput), the frontier price actually paid. Replayed: the traffic itself — real public support-style questions, timed replay; we play the customer. Extrapolated and labeled: monthly-bill projections. Simulated: nothing in the serving path. The demo console’s offline mode exists and is labeled MOCK in the header — mock numbers are never presented as measured. In a commodity market an unproven cost advantage is marketing; this MVP is built so that nothing shown is unproven. Known gap, stated rather than papered over: this demo exercises the latency-critical voice profile only. It does NOT yet show decode- and memory-heavy workloads (long-context agents, coding profiles, large batches) — the segment where the MI300X’s 192 GB of HBM should shine — because both AMD rentals arrived dead at the provider (2026-07-05). Until healthy MI300X capacity exists, that claim stays unmade, not simulated.

04

The MAX runtime, measured against a vanilla stack

The serving layer on every pool is Modular’s MAX runtime (pinned container modular/max-nvidia-full:26.4.0) — not a wrapper around another engine. To keep that claim honest, the same bench (same model, same A100 80GB PCIe class, same $1.39/hr, same docs-agent profile: 40 requests × concurrency 4, ~1,800-token prefill, 300-token decode) was run against a vanilla vLLM 0.9.1 container:

RUNTIME · QWEN2.5-14B · A100 80GB P50 / P99 TTFT P99 TPOT AGG TOK/S $/MTOK (MEASURED)
MAX 26.4.0 162 / 308.5 ms 20.8 ms 189.4 $2.04
vLLM 0.9.1 422 / 2440 ms* 22.5 ms 164.0 $2.35

*The vLLM pod was benched immediately after boot, so its tail (p95≈p99) captures first-batch warmup; the MAX pod had served prior traffic. The medians are the fair comparison: 2.6× faster first token, +15% throughput, ~9% lower steady-state TPOT on identical hardware and workload. Both reports are committed under bench-reports/ with the exact request profile embedded — rerun them yourself with ./dev bench. One workload profile on one GPU class is a data point, not a benchmark suite; Phase 0’s independent bake-off remains the standing commitment.

05

Architecture and build

Everything rides a production-shaped reference implementation — router, release engine, governance — with the BYOC-MVP layer adding the voice agent, the shadow mirror, the certifier, the bench, and this console. The whole control plane is itself hosted serverlessly (one Modal web app, scale-to-zero) so this site’s console drives it live with nothing installed; total GPU spend across every run so far: under $5, per-second billed, ledger-capped at $40. BYOC at full scale is this same loop with the pools living in the customer’s VPC — the demo’s egress class: in-VPC field is that future’s seed.
