01

What the MVP proves — and what it deliberately doesn’t

The strategy’s own honesty section calls trajectory-level parity “the least-proven claim in the plan.” This MVP attacks exactly that gap with the machinery of PRD Figure 1: shadow → certify → promote → instant rollback, run end-to-end on a real agent route. It does not claim the 40% decode advantage — that is Phase 0’s independent-benchmark work. It claims something a viewer can verify in the room: a route moved off a frontier API onto open silicon at certified quality, and then across vendors, with every number measured and every artifact rerunnable.

CERTIFIED MIGRATION · F1.2 + F1.3

Live traffic shadowed onto a candidate at zero user risk; quality certified against a hash-attested eval set; a signed (ed25519) certificate binds eval hash + model build + route config; promotion is one gesture, rollback is instant and armed for the life of the route.

PROOF HARNESS · F0.2 SLICE

One command — ./dev bench — measures p99 TTFT/TPOT and derives $/Mtok only from measured tokens/sec × declared pool price, for each pool. Reports embed the request profile so anyone can rerun them. SLO gates at p99, never averages.

CROSS-VENDOR · F1.4 RUNG 1

Route-level placement across NVIDIA A100 and AMD MI300X pools — the strategy’s “ships in 2026, nobody’s permission needed” rung, actually running. Same weights, both vendors, MAX-first serving; the placement follows the measured ledger, not an assertion.

02

The route: an agent that answers for Modular itself

The migrated route is docs-assist — a retrieval-grounded agent over Modular’s public documentation (MAX, Mojo, Mammoth, the skills repo). Every answer must cite the retrieved sources; ungrounded answers fail certification by construction. It is packaged as a skill in the conventions of Modular’s own skills repo — intended as a contribution, not a fork — and served MAX-first on both pools, with the bring-up driven by Modular’s import-model and debug-model skills: the §4.2 flywheel, demonstrated rather than described. A viewer can ask it anything, live, and watch which silicon answers.

03

Four minutes, three acts

ACT WHAT HAPPENS WHAT IT PROVES
0 · BASELINE The route serves from a frontier API on a customer-owned key at zero markup. A live question gets a cited answer; the chip on the answer shows FRONTIER, its latency, and its cost. The incumbent is real and the ledger reads it honestly — savings are reported against it, never against a synthetic counterfactual.
1 · MIGRATE Replayed traffic fills the shadow log; the certifier scores grounding + rubric against the eval set and checks p99 SLO from the bench report; the signed certificate reads PROMOTE_ELIGIBLE; one click promotes. The next live answer streams from the A100. The conversion machine of PRD Figure 1, end to end — quality and SLO gate the move; the ~60–90% cost drop is the reward, not the argument.
2 · CROSS-VENDOR The bench panel shows both pools’ measured $/Mtok at equal SLO; placement moves the route to the MI300X; a second certificate is cut; the next answer streams from AMD. One click rolls everything back in under five seconds. Cross-silicon serving is a working product motion, not a roadmap slide — and reversibility is what makes an enterprise say yes.
WHAT IS MEASURED, WHAT IS NOT — STATED PLAINLY

Measured: every latency, every tokens/sec, every open-pool $/Mtok (pod price ÷ measured throughput), the frontier price actually paid. Replayed: the traffic itself — real public support-style questions, timed replay; we play the customer. Extrapolated and labeled: monthly-bill projections. Simulated: nothing in the serving path. The demo console’s offline mode exists and is labeled MOCK in the header — mock numbers are never presented as measured. In a commodity market an unproven cost advantage is marketing; this MVP is built so that nothing shown is unproven.

05

Architecture and build

chat / replayer → router (shadow · placement · release · /v1/costs)
    ├→ frontier API  (incumbent · customer key · zero markup)
    ├→ docs-assist → MAX serve @ RunPod A100  80GB  (NVIDIA · act 1)
    └→ docs-assist → MAX serve @ RunPod MI300X 192GB (AMD · act 2)
certifier: evals(sha256, custody) + shadow log + bench SLO → signed cert → gates promote
console (this site ’s DEMO tab) ← polls /v1/costs · streams answers · shows certificates

Everything rides the existing reference implementation — the router, release engine, placement policy, and governance already in ai-native-pipeline; the MVP adds the agent service, the shadow mirror, the certifier, the bench, and this console. Eight build days, two rented GPUs, roughly $30–90 of total GPU spend. BYOC is the same loop with the pools living in the customer’s VPC via the repo’s existing Terraform interface — the demo’s egress class: in-VPC field is that future’s seed.

“Traffic shadowed, parity certified on evals the customer owns, promotion reversible in one click — and the savings are measured, not promised.”
